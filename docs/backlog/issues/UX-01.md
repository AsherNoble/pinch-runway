## Goal

Build the pings-first product shell and secondary snapshot dashboard against
the shared fixture contract.

**Priority:** P0 · **Lane:** frontend · **Size:** M
**Depends on:** RUN-02, RUN-03, ENG-04

## Acceptance criteria

- [ ] Primary surface is a notification/ping feed; the backup dashboard shows state, unpaid records, payer reliability, weekly draw, and lumpy items.
- [ ] Start from fixtures through the shared contract, never directly from Pinch payloads.
- [ ] Every demo/sandbox rendering visibly identifies its data source; no fake live visual state.
- [ ] Design for a sole trader collecting from their own clients through Pinch.
- [ ] Do not add bank, household, employee, portfolio, email, or calendar UI.

## Scaffold note

The initial page provides an honest fixture preview and data-source status. Keep
that provenance visible as the functional feed replaces it.
